AI Match-Stats Prediction — Model Flow Chart

How AI_match_stats_prediction.py turns raw football data into Win / Draw / Loss probabilities. The three machine-learning models are shown as dark blue boxes.

GBR — Match-Stats Predictor

Gradient Boosting. Trains one separate regressor per match-stat (xG, shots, possession…) from pre-match data, using 5-fold out-of-fold predictions for training rows. Falls back to the median if a stat has fewer than 25 usable rows or no variance. Used so future games — which have no stats yet — still get a "General" signal.

Surrogate — Weight Picker

A meta-model (GBR or Neural Net). Learns from past runs which weight settings score well, so the search skips bad combinations instead of guessing randomly. Activates only after 100 valid history rows survive filtering (same stats-mode, source-mode, schema, and non-empty scores). History is always read from the reference folder.

BART — Outcome Model

Bayesian Additive Regression Trees (200 trees). The real predictor — but it estimates only the goal difference. The Win / Draw / Loss probabilities are produced afterwards by a normal-curve approximation (using the training residual spread and a ±0.5-goal "draw zone"), not by BART directly.

Caveats worth noting in the paper

  • Re-test mode uses real in-match stats by default. When re-testing past games the code defaults to the actual statistics, so it is a diagnostic check, not a pure "pre-match only" backtest.
  • BART trains on 80% of the data. An 80/20 split is created, but the 20% validation slice is never used afterward — so BART only ever sees the 80% training portion. Flag this if it was unintended.
  • Possible information leak in season strength. Each team's season-long average strength is computed from all played games before the test games are removed, so a past game's own result can slightly influence its own prediction inputs.
