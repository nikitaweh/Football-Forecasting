Main System Pipeline
Draw LEFT-CENTER, top-to-bottom
START — Raw CSV Data
Feature Engineering
• Base team strength (season avg goals for/against)
• Rolling last-5 form (goals, results)
• H2H features (K recent meetings, reliability scaling)
• Weather context (temp, wind, rain)
• HomeTeamID / AwayTeamID
⬡ MATCH_STATS_MODE?
"predicted" → run GBR layer (future & honest backtest)
"actual" → use real stats (reference eval only)
"off" → skip stats entirely
Match Stats Prediction Layer GBR
• One GradientBoostingRegressor per stat target
• 5-fold cross-validation (leakage-safe OOF for training rows)
• Pre-match inputs only (no current-match stats, no result)
• Targets: Possession, Shots, ShotsOnTarget, Passes, PassAccuracy, Fouls, YellowCard, RedCard, Offsides, Corners (Home & Away)
Post-process: clip possession 0–100 · normalize to sum 100 · clip count stats ≥ 0 · round integers
Outcome Model BART
• 200 Monte Carlo runs — sample one weight per feature + one H2H_K integer per run
• Feature weighting groups: Goal Creation (high) · Game Control (med) · Discipline (low)
• H2H reliability scaling per sampled K
• Median imputation for missing values
• Train BART on GoalDiff = HomeGoals − AwayGoals
Convert GoalDiff → Probabilities
WinProb · DrawProb · LoseProb (logistic / threshold mapping)
Estimated scoreline (Home Goals · Away Goals)
Surrogate Selection
• Load surrogate_run_history.csv (filtered by MatchStatsMode)
• Select top runs by Pareto front (accuracy vs. calibration)
• Re-use best weight configurations for future predictions
Outputs
📄 prediction_weight_runs.csv — all 200 runs
📄 prediction_weight_run_summary.csv — aggregated
📄 pareto_front.csv (reference mode)
📄 future_candidate_ranking.csv (future mode)
📄 predicted_match_stats.csv (when mode = predicted)
Leakage Controls (critical!)
① Match-stats GBR uses only pre-match inputs (no result, no in-game stats)
② In reference mode: held-out matches are removed from training set
③ In predicted mode: training rows receive OOF stat predictions, not their real stats
④ BACKTEST_DATE_CUTOFF filters all training rows with Date ≥ cutoff
Feature Groups (in BART)
▶ Goal Creation (highest weight)
  xG proxy, Shots on Target, Shots

▶ Game Control (medium weight)
  Possession, Passes, Pass Accuracy

▶ Discipline / Set Piece (lowest weight)
  Fouls, Yellow Cards, Red Cards, Corners, Offsides

Surrogate System

Filtered by MatchStatsMode (no mixing actual / predicted)
Pareto front: accuracy vs. calibration trade-off
Best runs reused in future mode
Modes
PREDICTION_MODE: future | reference
MATCH_STATS_MODE: predicted | actual | off
future + predicted → honest real-world prediction
reference + actual → upper-bound evaluation
reference + predicted → end-to-end honest backtest
future + actual → BLOCKED (not available pre-kickoff)

Key guarantee
The BACKTEST_DATE_CUTOFF ensures that when predicting MD N, the model has never seen any data from that matchday or later. This simulates exactly what a real-time prediction would look like.

Key difference vs. backtesting
In future mode, there are no actual results to validate against yet. The pipeline runs exactly as in backtest but outputs a ranked list of confident predictions for the next matchday. Validation happens retroactively once the games are played.
